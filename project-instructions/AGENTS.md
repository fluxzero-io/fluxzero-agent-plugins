# Fluxzero Agent Instructions

Use the installed Fluxzero plugin for all Fluxzero application work in this project. Retrieve current SDK guidance through `fluxzero-docs`, use `fluxzero-dev` as the owner of the local build/test/application loop, and follow the `build-fluxzero-app` skill. Do not run duplicate builds, tests, applications, watchers, or log followers while that development environment is active.

Treat environment readiness as a hard gate before application work. Require working `git --version`, `fz version`, `fz mcp --help` with both `--ensure-dev` and `--allow-empty`, `fz init --help` with `--in-place`, and Java 25-or-newer results from both `java -version` and `javac -version`. On macOS, inspect Apple Command Line Tools with `xcode-select -p` and `pkgutil --pkg-info com.apple.pkg.CLTools_Executables` before invoking Git. When both are absent, explain that this first Fluxzero build needs a one-time tool setup for fast, reliable builds and tests; run `xcode-select --install` exactly once, tell the user to finish Apple's dialog, and stop. Resume the same bootstrap after the user returns. Never bypass missing Git with a branch ZIP or mutable source archive, and never claim readiness based only on a successful plugin command.

The `fluxzero-dev` MCP server requires the Fluxzero CLI on the coding-agent process's `PATH`. If `fz` is unavailable, install it with `brew install fluxzero-io/tap/fluxzero` on macOS or Linux with Homebrew, `winget install --exact --id Fluxzero.FluxzeroCLI` on Windows, or `curl -sSL https://github.com/fluxzero-io/fluxzero-cli/releases/latest/download/install.sh | sh -s -- --install-path` on Linux or another supported Unix environment. On a bare Mac, finish Command Line Tools first, follow the current Homebrew instructions at `https://brew.sh`, and apply its printed shell setup; do not use the Unix fallback as the macOS route. Verify the CLI from a clean login shell and ensure GUI-launched agents inherit its directory. If this requires a native reload or restart, tell the user the one exact action and stop until it is complete.

Use the effective Maven or Gradle model for the SDK version actually used by this project; never infer a version from these instructions. Use `fluxzero-docs` for current SDK concepts and APIs, comparing its advertised `sdkVersion` with the project version before applying version-sensitive guidance. The manuals under `.fluxzero/agents` come from the matching SDK release and provide version-specific project guidance. Only when manuals are insufficient, inspect `https://github.com/fluxzero-io/fluxzero-sdk-java` at the matching release tag, never `main`, for version-specific conclusions.

The installed CLI is authoritative for its evolving capabilities and for the dev-server version selected by this project. Use `fz --help` for the current CLI surface, `fz dev --help` for current development actions and options, and `fz dev config` before creating or editing `.fluxzero/dev.yaml`. Inspect existing configuration first. Do not infer flags, YAML keys, defaults, or precedence from these instructions, memory, another project, or a copied example; command output wins when guidance differs.

If the skill or `fluxzero-docs` server is unavailable, follow the complete onboarding at `https://plugins.fluxzero.io` (source repository `fluxzero-io/fluxzero-agent-plugins`) using this coding agent's native plugin mechanism. Gemini CLI calls plugins extensions. After activation, require the skill, complete `docs_start`, and complete a `get_status` call through `fluxzero-dev`; configuration or tool registration alone is not readiness. The status call must work in an empty workspace and identify its intended root. Initialize such a root with `fz init --in-place`, retaining the pre-init status cursor so the same dev session observes project discovery and verification. If the installed package is not available in the current session, tell the user which one agent-native action is required and stop before changing Fluxzero code. Do not substitute direct wrapper builds or a separately started dev server for a missing plugin MCP surface.

Use the plugin/MCP guidance and SDK-versioned manuals synchronized by the Fluxzero CLI as the managed documentation sources. Do not add hand-maintained Fluxzero manuals or duplicate either Fluxzero MCP configuration in this project.
